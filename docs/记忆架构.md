# 记忆与情绪怎么分工

一开始我把记忆和情绪放在同一套东西里，结果是两套人格互相打架。现在的分工是：

```
事实 / 经历  →  数字生命卡（whale-bridge）
情绪 / 激素  →  fish-growth
梗 / 黑话    →  memewiki（只在指定会话）
```

## 卡：只记事实

卡是 SYNAPSE-1024，一个本地 Python 服务（`127.0.0.1:8848`），数据在 `card.db`。每条记忆在库里是三份东西：

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `raw` | 原话，一字不改 | 溯源、导出 |
| `core` | 主干（≤40 字，超了按标点截断） | 省 token 的召回 |
| `detail` | TIME / PLACE / EMOTION / MODIFIER / ACTION 子句 | 补细节 |

所以「召回时措辞被拧过」是卡的渲染层做的，不是数据被改：它拿 `core` 当主干，再从 `detail` 里挑一条不重复的子句用「，还说「…」」接上去。原文一直在 `raw` 里。要原话就把 `raw` 拿出来。

卡自己的衰减按 `region` 走，不是按类型：

```
flash 0.30 · fact 0.50 · self 0.60 · habit 0.70 · preference 0.80 · episode 1.00
```

数值越小衰减越慢。所以「称呼、身份、偏好」这类东西要落进 `self` / `preference`，别丢在 `episode` 里跟着聊天流一起淡掉。

## fish-growth：只记状态

一次对话结束后判断一次情绪，写进 `~/.dsh/fish-growth/<profileKey>.json`：

- 17 条情绪轴，各有半衰期；
- 4 条激素轴，由情绪推动、13.9h 回归基线，带昼夜节律；
- 性格与美德，需要连续证据才会提议改动，人批准后才生效。

激素不直接说「你要活泼一点」，而是给出**倾向描述**（「话比平时多一点，愿意主动起话头」/「有点懒，不想多说」）。实测「描述状态」比「下命令」稳定得多，而且不会在回复里报数值。

## 为什么不合

- 两套情绪 = 两份互相矛盾的心情，模型会挑一个信，另一个白算；
- 两套人格 = 提示词里两段自我描述打架；
- 两套写入 = 同一句话记两遍，召回时重复且占 token。

## 上下文满了怎么办

交给 DSH 的压缩器（`preset` 里的 `compaction-basic` / `command-compact` / `tool-result-pruner`）。压缩只影响「这一轮能看到什么」，**不碰卡，也不碰情绪状态文件**——那两份是按需读取的，不在上下文里长期占位。

所以「记不住」通常不是上下文满了，而是：

1. 那句话根本没写进卡（没调 `mind_report`）；
2. 写进去了但落在 `episode`，衰减得快；
3. 写进去了，但 `mind_context` 没被调用（模型忘了）。

排查顺序就按这三条走。
