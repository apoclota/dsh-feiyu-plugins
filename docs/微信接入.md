# 微信接入：三条路，各自的限制

个人微信没有开放的发消息接口，能用的办法只有三种。这三条我在本机都跑通了，下面是它们真实的边界，别指望一条路包打天下。

## 1. 官方 iLink（`dsh-wechat-media` 插件）

收消息最稳：插件长轮询 iLink，把收到的消息转成会话事件，机器人按正常流程回复。

但外发有两个硬限制，都是服务端行为，不是代码没写：

```
sendMessage ret=-2 errmsg=prepare failed —
the WeChat conversation window is closed: iLink sends only with a fresh
context token from a recent inbound message
```

- **只能被动回**：必须「刚收到过消息」才拿得到可用的 context token；主动找话说会被拒。
- **发不了语音气泡**：插件里 `voiceDeliveryFor({platform})` 对微信恒返回 `file`，音频一律当文件发。原因写在源码注释里：个人微信只认 SILK 气泡 + `voice_item.playtime`，作者实测「播放窗口内发 mp3」和「SILK + playtime」两次都是接口收下、客户端丢弃。

所以这条路适合：**回消息、发文字、发文件**。

## 2. UIA 直发（`tools/wx-say.py`）

既然客户端就登在这台机器上，就直接操作它：找到聊天窗口 → 写进输入框 → 回车。

安全阀是我被咬过一次之后加的：

- 只允许私聊，标题必须精确匹配（防止发错群）；
- 输入框里已经有字就不发（防止把别人没发出的草稿顶掉）；
- 回车后回读输入框，**必须为空**才算成功；
- 默认要求系统键鼠空闲 ≥ 8 秒（`GetLastInputInfo`），你在打字时它不会抢焦点；`--force` 可以跳过，但别在自动流程里用。

这条路能主动说话，代价是会短暂占用前台窗口。

## 3. 语音气泡（`tools/wx-voice-bubble.py`）

微信 4.x 不暴露「按住说话」这种具名按钮，所以做法是模拟按键：

1. 本地 TTS（`http://127.0.0.1:9880`）合成 wav；
2. 打开目标私聊，核对标题与输入框；
3. `Ctrl+Tab` 按住（`keybd_event`），把 wav 播到虚拟声卡 `CABLE Input (VB-Audio Virtual Cable)`；
4. 松开 → 微信把它录成一条语音发出。

要点：

- 必须装 VB-CABLE，且录音设备选它；
- 4.x 的窗口类是 `mmui::MainWindow`，标题控件和输入框的 AutomationId 与 3.x 不同（脚本里写的是 4.x 的值）；
- 失败要发一次 Backspace 取消，否则会留下一条半截录音；
- 同样有「你在用电脑就不发」的空闲检查。

## 语音合成接哪

`dsh-wechat-media` 的 `voice.js` 里原本硬编码一个 TTS 命令。我把它改成可覆盖：

```js
const DEFAULT_TTS_CMD = process.env.DSH_TTS_CMD?.trim()
  || "node <你的 tts 脚本>";
```

配上 `tools/tts-9880.mjs`（读文本文件、请求 9880、写回音频文件）就能用本地音色。这属于**改第三方插件**，升级插件时要重新打这个补丁；补丁只有一行默认值，改了也容易回滚。

## 一句话总结

| 需求 | 用哪条 | 限制 |
| --- | --- | --- |
| 回消息 | iLink | 只能被动 |
| 主动发文字 | UIA 直发 | 占用前台，键鼠空闲才发 |
| 主动发语音气泡 | UIA + 虚拟声卡 | 要 VB-CABLE，4.x 专用 |
| 发音频文件 | iLink | 不是气泡 |

想让它「随时能找你」，最省事的其实是把 3 条都留着：回复走 iLink，主动说话走 UIA，语音气泡当彩蛋。
